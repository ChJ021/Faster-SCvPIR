# Experiment-result policy

Formal `paper-v1` output is generated by
`native/scripts/summarize-paper-results.sh`. A publishable result directory must
contain:

- `runs.csv`: one row per successful native run;
- `summary.csv`: mean, sample standard deviation, median, range and two-sided
  95% Student-t interval;
- `speedups.csv`: ratios of means plus repetition-paired same-host speedups and
  their uncertainty;
- `comparison-small-client.csv`: explicitly qualified source-paper references;
- `manifest.json`: hashes of all input logs, the frozen profile and baseline
  transcription.

Raw logs, interrupted attempts and machine-local schedules remain under
`native/logs/` and are ignored by Git. The summarizer is fail closed: incomplete
runs or schedules, mismatched manifest hashes, schedule/log disagreements and
absent correctness markers cannot enter a formal table.

## Evidence placement

- Main-text evidence: correctness, same-host total/component preprocessing
  speedups, uncertainty, hint-size cost and online-cost stability.
- Methods/repository evidence: full environment, source/binary hashes, order
  seed, query indices and raw timing stages.
- Supplementary evidence: per-run rows, memory traces and secondary metrics.
- Cross-paper reference: only the values actually reported by Small-Client
  vPIR, with its Sapphire Rapids/AVX-512 hardware shown alongside the local
  host. A cross-hardware ratio is never the primary speedup.

The source paper reports layouts and query-level results for 512 MiB and 1 GiB,
but no 2 GiB or 4 GiB measurements. Those larger columns therefore remain
`not-reported-by-source` rather than being interpolated.

## Historical data

Older local result directories may include runs that predate the full-width
sampling and Eigen row-population fixes, or pilot runs collected in a fixed
profile order. They are retained only for provenance and must not be copied into
`paper-v1` output. A formal run must use the current manifest hash and the
balanced matrix scheduler.
